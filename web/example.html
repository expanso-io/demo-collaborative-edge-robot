A job for the robot

PresenterExplorer

One card, one word, three devices

A camera chooses a destination. A microphone gives permission to move. Six local Expanso Edge pipelines connect recognition, coordination and device state. Raw images and audio stay on the Mac; only small JSON envelopes enter the pipelines.

The stage uses map adapters for the rover and drones. Each adapter accepts the same movement commands a hardware adapter must implement. Physical hardware integration is future work.

The coordinator owns the rules: confident cards select a destination, uncertain recognition holds movement, and stop wins over go within 1.5 seconds. The explorer shows committed fixture records run through the actual pipelines by the public check.

Run locally

Install Expanso Edge and CLI v2.1.21, just, uv, and Node.js. From this repository, run the fixture check without a camera, microphone or credentials:

just public-check
just up
just down

The presenter runs at 127.0.0.1:4180. Its first start installs pinned speech dependencies. Grant camera and microphone permissions when ready. Stop the presenter before running the fixture suite because both use the local event bus.

Deploy the local jobs

Stage 1 runs six Edge nodes on this Mac. The launcher deploys each checked-in job to its matching local node and stops all six with just down. To redeploy the coordinator while the launcher is running:

expanso-cli --endpoint http://127.0.0.1:4200 \
  job deploy pipelines/coordinator.yaml

These loopback addresses are for this local stage. A hardware rollout requires device adapters, authenticated encrypted transport and node routing before deployment through Expanso Cloud. The hardware buying guide documents that later work; this example makes no physical deployment claim.
